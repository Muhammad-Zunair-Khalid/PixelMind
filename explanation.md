# Smart Gallery (PixelMind): Architecture & Data Flow

This document provides a concise overview of the inner workings of the Smart Gallery project, tracing how data enters the system, how it is processed by various AI models, where it is stored, and how it is ultimately retrieved.

---

## 1. The Inputs (Data Entering the System)
All interactions begin at the frontend (HTML/JS) and are sent to the FastAPI backend via specific endpoints:
*   **Image Uploads (`/api/upload`)**: The user selects an image file from their device and uploads it to the gallery.
*   **Semantic Search (`/api/search`)**: The user inputs a natural language text query (e.g., *"a black car"* or *"playing at the beach"*).
*   **Contextual Chat (`/api/chat`)**: The user opens a specific image and types a question to the AI assistant regarding that image.

---

## 2. The AI Pipeline (The "Middle")
When an image is uploaded, it is intercepted by a 3-step artificial intelligence pipeline before any data is permanently saved:

1.  **YOLOv8 (Object Detection):** The backend passes the image to a locally hosted YOLOv8 model. It scans the image and returns a structured list of localized objects and their confidence scores (e.g., `[{"label": "person", "confidence": 0.95}, {"label": "dog", "confidence": 0.89}]`).
2.  **BLIP (Image Captioning):** The exact same image is passed to a locally hosted BLIP model. BLIP interprets the overall scene and generates a natural, human-readable descriptive sentence (e.g., *"A person walking a dog in the park."*).
3.  **Sentence-Transformer (Vector Embedding):** The caption generated by BLIP is passed into the MiniLM embedding model. This model translates the English sentence into a 384-dimensional mathematical array (a vector). This vector allows the computer to understand the *semantic meaning* of the caption rather than just the raw text.

---

## 3. Storage Architecture
Because the system handles different types of data, it utilizes a hybrid storage approach:

*   **Local File System (`uploads/` folder):** The physical raw image file (`.jpg`, `.png`) is saved directly to the server's hard drive.
*   **MySQL (Relational Database):** Stores the traditional, structured data. This includes the `image_id`, the BLIP text caption, the YOLO object tags, the upload timestamp, and the relationship mapping the image to the user who uploaded it.
*   **Qdrant (Vector Database):** Dedicated exclusively to storing the high-dimensional mathematical vectors generated by the Sentence-Transformer.

---

## 4. The Outputs (Data Leaving the System)
The system retrieves and outputs data in intelligent ways depending on the user's request:

*   **Executing a Search:** 
    When a user searches for *"puppy playing"*, the backend does not just look for the word "puppy" in the MySQL database. Instead, it uses the Sentence-Transformer to convert the search text into a vector. It then queries **Qdrant** to find the stored vectors that mathematically match the closest. Qdrant returns the corresponding Image IDs, which the backend uses to fetch the actual images from MySQL and display them to the user.
*   **Executing a Chat:** 
    When a user asks the AI a question about a specific image, the Llama-3 model (via the Groq API) cannot physically *see* the image. Instead, the backend retrieves the **BLIP Caption** and **YOLO Objects** associated with that image from MySQL. It injects this metadata into a hidden system prompt (e.g., *"The user is asking about an image. The image shows: A person walking a dog. Objects detected: person, dog."*). The LLM reads this text context and formulates a reply, creating the illusion of visual awareness.
